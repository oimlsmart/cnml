# TODO.FULL/03 — Per-Recommendation CNML issuance

## Problem

The third scenario: the per-Recommendation CNML certificate for a specific
measuring instrument. This cert is signed by the IA (or a delegated
manufacturer) using an IA intermediate certificate. It is bound to the
Type Approval Certificate details: instrument model, serial number,
manufacturer, accuracy class, and the OIML Recommendation it conforms to.

## Scenario

The user selects an existing IA intermediate certificate (generated by
scenario 02 or uploaded). The user fills in the instrument details.
The page signs the CNML payload with the IA's signing key. The output
is a signed CNML XML document that chains to the IA intermediate and
the BIML Root.

## Scope

- Page route: `/issue/per-recommendation`
- Vue island: `apps/cnml-web/src/islands/issuing/PerRecommendationFlow.vue`
- Astro page: `apps/cnml-web/src/pages/issue/per-recommendation.astro`

## Implementation status

Shipped in this branch. The page lets the user pick a Recommendation, fill
in instrument details (model, serial, manufacturer, accuracy class), generate
a signer key, sign the CNML payload, and download the result. The signer key
is the IA's key, generated in-session for this demo. In production, the
IA would use its threshold quorum to sign.

## Tests

- Build: the route produces a page
- Flow: pick R60, fill in instrument details, sign, download
- Output: the JSON contains the signed CNML payload
